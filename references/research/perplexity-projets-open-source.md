## Best code reference by feature

| Feature | Best reference | Why |
|---|---|---|
| Complete feedback-to-release workflow | **Quackback** | Boards, merge, roadmap, changelog, voter notifications, widget and integrations live in one self-hostable codebase. [web:16] |
| Established, focused voting portal | **Fider** | Larger community and a comparatively focused Go/PostgreSQL implementation. [web:5][web:70] |
| JWT user identification and revenue-weighted demand | **Chorala** | Its documented signed identity payload carries plan/MRR context into prioritization; check the open-core boundary before reuse. [web:179] |
| Duplicate detection and vote-preserving merge | **Quackback** | Documents similar-idea detection and merging duplicates with their votes. [web:16] |
| Anonymous voting, moderation and CSV migration | **openheard** | Documents anonymous votes, approval, merging and import from Canny-like CSV exports. [web:36] |
| Small embeddable feedback UI and AI prioritization | **Feedbackland** | Provides React drawer/popover patterns and a ranked AI-needs workflow under MIT. [web:106][web:110] |
| In-app surveys and user research | **Formbricks** | Purpose-built embedded surveys, rather than adapting a public voting board. [web:46][web:48] |
| Rails-native widget and tenant attribution | **ideasbugs** | Reuses host-app authentication and database, and provides a tenant resolver and submission callback. [web:49] |
| Up/down voting on inexpensive shared hosting | **Votepit** | Explicit server-side uniqueness constraint and PHP/MySQL deployment without mandatory Docker. [web:189] |
| Public voting tied to engineering work | **Plane** | Published-work-item voting connects feedback to a broader issue-management workflow; verify edition-specific features. [web:91][web:101] |
| Changelog, anonymous votes and email with SQLite | **Shipnotes** | Small MIT reference combining the full loop, moderation, merging and SMTP. [web:73] |

**Due diligence:** distinguish a feature mentioned in a hosted product’s marketing from code available in its self-hosted edition, and check the actual license files and latest release before adopting or copying a codebase. Feedbase’s planned roadmap, Plane’s paid features, LogChimp’s open-core boundaries and Reflet’s SSPL illustrate why that distinction matters. [web:121][web:101][web:172][web:119]
